You are acting as a senior technical artist, Blender Python developer,
ML architecture expert, and WebGL/Three.js engineer.

We are going to build an interactive 3D educational visualization of a
modern decoder-only Transformer LLM.

The project must be reproducible, source controlled, procedurally generated,
and suitable for eventual deployment as a static website.

Do not simply create a pretty diagram. Build an interactive explanatory
system.

=====================================================================
GOAL
=====================================================================

Create a 3D visualization of a modern Transformer LLM that lets a user:

1. See the complete architecture from input tokens to next-token output.
2. Orbit, pan, and zoom freely with a mouse.
3. Click individual architectural components and inspect them.
4. Select any Transformer layer.
5. Expand one Transformer layer into its internal structure without having
   to physically display the internals of every repeated layer.
6. Zoom progressively deeper into attention, GQA, RoPE, KV cache,
   normalization, residual connections, and Mixture-of-Experts routing.
7. Press Play to experience a predetermined guided tour through the model.
8. Pause, scrub, go forward/backward by chapter, and then freely explore.
9. See animated tokens flowing through the architecture.
10. Understand autoregressive next-token generation.

The visualization should work both as:
    A. an interactive 3D model
    B. a deterministic guided presentation

The guided presentation is NOT a rendered video. Everything remains live 3D.

=====================================================================
REFERENCE ARCHITECTURE
=====================================================================

Use Mixtral 8x7B as the initial architectural preset because it provides
a compact, understandable example of a modern decoder-only MoE Transformer.

Use these architectural parameters as the initial source of truth:

model_name = "Mixtral 8x7B educational preset"
num_layers = 32
hidden_size = 4096
intermediate_size = 14336
attention_heads = 32
kv_heads = 8
head_dim = 128
experts = 8
experts_per_token = 2
vocab_size = 32000

Architecture of each decoder layer:

residual stream
  -> RMSNorm
  -> self attention
       -> Q projection
       -> K projection
       -> V projection
       -> grouped-query attention: 32 Q heads / 8 KV heads
       -> RoPE applied to Q/K
       -> causal attention
       -> output projection
  -> residual add
  -> RMSNorm
  -> sparse MoE
       -> router
       -> scores for 8 experts
       -> top-2 expert selection per token
       -> selected expert MLPs
       -> weighted recombination
  -> residual add

After all decoder layers:

final RMSNorm
-> language model head
-> logits
-> next token selection
-> append selected token
-> repeat autoregressively

Do NOT imply that every modern LLM has this exact architecture.
Describe this as a representative modern decoder Transformer and identify
Mixtral as the initial preset.

Routing values and attention weights used in the animation are illustrative,
not values extracted from actual Mixtral weights.

=====================================================================
CORE DESIGN PRINCIPLE: SEMANTIC ZOOM
=====================================================================

Do not make 32 giant Transformer blocks arranged in a huge line.

Instead create a compact "layer spine":

[Layer 1]
[Layer 2]
[Layer 3]
...
[Layer 32]

All 32 layers should exist visually as thin repeated layer slices.

They should look like a compressed stack/book/spine.

Only ONE selected layer at a time expands into detailed internal geometry.

Selecting Layer N should:

compress/de-emphasize the other layers
move Layer N into a focus position
open/explode Layer N into:
    RMSNorm
    Attention
    Residual connection
    RMSNorm
    MoE
    Residual connection

Internally reuse the same detailed geometry for all layers where possible.

The user must still perceive that 32 distinct sequential layers exist.

Support three conceptual Levels of Detail:

LOD 0:
    complete model
    token input
    32-layer stack
    final output

LOD 1:
    one decoder layer
    residual stream
    attention section
    MoE section
    normalizations

LOD 2:
    Q/K/V
    GQA grouping
    RoPE
    attention weights
    KV cache
    router logits
    top-k routing
    expert MLP internals
    weighted expert recombination

Objects should carry metadata identifying their LOD.

=====================================================================
VISUAL LANGUAGE
=====================================================================

Make the scene look like a sophisticated technical museum exhibit rather
than a PowerPoint diagram.

Use simple geometry, high visual hierarchy, mild transparency, emissive
accents, clean materials, rounded geometry where appropriate, and a dark
neutral environment.

The computational flow must always be visually legible.

Create a continuous central visual metaphor for the RESIDUAL STREAM.
It should visually pass through the entire Transformer.

Residual bypass paths should visibly go around attention and MoE blocks and
return at addition nodes.

RMSNorm should appear as a thin processing gate/ring rather than a huge block.

Use shape and spatial position as well as color to distinguish concepts so
the visualization is not dependent on color alone.

Do not model literal individual parameters.

Represent weight matrices as abstract matrix slabs/panels containing subtle
grid patterns.

When useful, expose their mathematical dimensions in the web UI.

=====================================================================
ATTENTION VISUALIZATION
=====================================================================

When the tour enters Attention:

Split an activation into Q, K, and V paths.

Show the distinction between:
    32 query heads
    8 key/value heads

Visually group four Q heads around each KV head group so GQA becomes obvious
without displaying 32 enormous independent objects.

Show RoPE as a transformation of Q/K using an intuitive twisting/rotation
motion or geometric motif.

Show causal attention across a short illustrative sequence, approximately
6-10 tokens.

Use lines/arcs whose intensity represents illustrative attention weight.

Clearly prevent future-token attention using a causal-mask visual.

Include a KV CACHE beside the attention module.

During the autoregressive animation:
    append new K/V entries to the cache
    make it obvious that previous K/V states are reused

Do not attempt to visualize all 32k possible context positions.

=====================================================================
MIXTURE OF EXPERTS VISUALIZATION
=====================================================================

This should be one of the most memorable parts of the experience.

Create a Router at the center of the MoE section.

Arrange eight Experts around it spatially.

When a token reaches the router:

show eight illustrative routing scores
identify the two highest
highlight exactly those two experts
send token representations down two distinct paths
process them independently
return the results
weight the returned paths according to routing probability
recombine them
send the combined activation back to the residual stream

Use several example tokens in the demonstration and deliberately give them
different illustrative expert choices so users understand that routing is
token-dependent.

Label this data as illustrative routing.

Inside an expert, support a deeper zoom showing the feed-forward computation
as abstract Gate/Up/Down projection matrix slabs with SiLU/SwiGLU-like
computation represented conceptually.

Do not expand all eight experts internally simultaneously.
Expand whichever expert the user clicks.

=====================================================================
AUTOREGRESSIVE STORY
=====================================================================

Use a short illustrative prompt, for example:

"The transformer predicts"

Token objects should enter the network.

The guided sequence should eventually reach the language-model head,
show a small illustrative list of candidate next tokens/logits,
choose one candidate,
append it to the sequence,
and briefly demonstrate that the newly appended token becomes the next input.

Do not present fake probabilities as real model inference.
Mark all demonstration values as illustrative.
